# v1.0.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native execution chosen by the operator). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish QuickCull `v1.0.0` on GitHub with a universal app zip, release notes that install it, and docs corrected against the shipped code.

**Architecture:** Docs-only commit on `main`, one `xcodebuild` Release build from that commit, a tagged annotated tag, then a `gh release create` with the zip asset. No product behavior changes.

**Tech Stack:** `xcodebuild`, `ditto`/`zip`, `shasum`, `git`, `gh`.

**Spec:** `docs/superpowers/specs/2026-10-28-v1-release-design.md`

## Global Constraints

- No product code changes; this ships `eb7e190` behavior. Comment-only fix to a wrong defaults domain is allowed.
- `MARKETING_VERSION = 1.0` → tag `v1.0.0`.
- Ad-hoc signing only: `ENABLE_HARDENED_RUNTIME = NO`. Notes must state the Gatekeeper step.
- Asset name: `QuickCull-1.0.0-macOS-universal.zip`, containing `QuickCull.app`.
- Minimum macOS: 14.0. Architectures: x86_64 and arm64, both required in the app binary and `libraw.dylib`.

## Review Focus

- **Gatekeeper on first launch:** a downloader double-clicks, sees "unverified developer", and gives up if the notes don't say right-click → Open. The notes carry it twice: prose and a Terminal alternative.
- **Stale README numbers:** 227 tests is the verified count (80 s suite, 0 failures). Any other number in the README or `AGENTS.md` is a bug.
- **Wrong defaults domain:** the app reads `UserDefaults.standard`, so the domain is `com.quickcull.app`, not `com.quickcull`.
- **Zip round trip:** a zip that strips the bundle structure or the signature makes the release useless even though the local build is fine. Verify by downloading the published asset.
